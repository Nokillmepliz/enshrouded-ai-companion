## Резервная копия до установки

Подготовлены [конфигурация с найденными путями](../config/first-test-backup.json) и [scripts/backup.py](../scripts/backup.py). Включаются вся папка игры (в том числе существующий её подкаталог `backup`), полный каталог Steam `1203620`, локальные сохранения/настройки, appmanifest и личность, если уже создана. Существующий `game\backup` не считался нашей проверенной копией.

Расчёт на момент подготовки: **216 файлов, 51 887 751 684 байта (48,32 ГиБ)**. На C: около 577 ГиБ свободно, на D: около 405 ГиБ. Скрипт повторно проверяет место перед копированием; фактические числа могут измениться.

Только чтение, можно повторять без установки:

```powershell
Set-Location 'C:\Enshrouded-ai-companion'
$Python = 'C:\Enshrouded-ai-companion\.tools\python\python.exe'
$Game = 'D:\SteamLibrary\steamapps\common\Enshrouded'
Get-FileHash -LiteralPath "$Game\enshrouded.exe" -Algorithm SHA256
& $Python scripts\backup.py
```

После согласования этапа: дождаться синхронизации Steam, выйти из Steam, закрыть игру/сервер. Затем выполнить копирование:

```powershell
& $Python scripts\backup.py --execute
```

Проверка процессов выполняется перед копированием и после него. Источники не перезаписываются, новая папка имеет уникальное имя. Ссылки/junction запрещены, пересечение назначения и источников запрещено. Для каждого файла сравниваются SHA-256 скопированного потока, повторно прочитанного источника и копии; затем сравнивается состав и метаданные исходного дерева. Если что-то изменилось/не прочиталось, успех не заявляется. Не запускать Steam или игру в течение копирования: это не файловый snapshot и не блокировка всех сторонних программ.

Успех: exit code=0, `verified=true`, путь `manifest.json`; внутри него также `verified=true` и хеш каждого файла. Частичная копия остаётся для диагностики с `verified=false`, установка после неё запрещена. Команда может работать долго: читается вся игра несколько раз. Скрипт ничего не восстанавливает и не удаляет.

После создания отдельного LOCAL тестового персонажа/мира **ещё до spawn** выйти из игры, дождаться синхронизации и выйти из Steam; сделать вторую копию тем же скриптом. Это даст состояние для отката самого теста, которого в первой копии ещё нет. Затем пользователь снова запускает Steam, игру и тот же тестовый мир.

## Последовательность после отдельного подтверждения

1. Получить/проверить архив EMF, повторить проверку EXE, создать проверенную резервную копию. До этого не выполнять установку.
2. При закрытой игре установить EMF manual штатным `install.ps1` с явным `-Game 'D:\SteamLibrary\steamapps\common\Enshrouded'` и `-IfBackupFails Stop`. Из каталога распакованного официального пакета это выглядит так: `powershell -NoProfile -File .\install.ps1 -Game 'D:\SteamLibrary\steamapps\common\Enshrouded' -IfBackupFails Stop`. Пока эта команда не выполнялась.
3. Распаковать наш ZIP в `$Game\emf\mods`, проверить отсутствие двойного `aic_body\aic_body`. В `[aic_body]` файла `emf\config\aic_body.ini` выставить `enabled=1`. Сохранять остальные секции существующих ini.
4. Оставить включёнными только Lua-host и aic_body для первого испытания. В частности, выключить штатный Companion, pet_follow, Beastmaster, Quick Stack и Clock (последние два включены в EMF по умолчанию). Конфигурация каждого мода: `emf\config\<id>.ini`, секция `[<id>]`, `enabled=0`. Это тоже часть будущей согласованной установки.
5. В `emf\emf_core.ini` настроить:

   ```ini
   [debug]
   bridge=1
   bridge_verbose=1
   ```

   `bridge_verbose` логирует подключения/отключения; команды и ответы пишет наш клиент. Подтверждено [документацией bridge](https://github.com/matenm/emf-enshrouded/blob/08d600155fcadc8e45cc9c6f3932a67c717345be/docs/modding/debug_bridge.md#L7-L27).
6. Пользователь запускает Enshrouded через Steam, создаёт отдельного **LOCAL** персонажа `Body Test` и отдельный **LOCAL** мир. Записать имя и номера из диагностики ниже; не угадывать их по порядку видимых карточек. Сделать вторую копию, как описано выше. Основной мир не открывать.
7. При загруженном тестовом мире в консоли EMF проверить `mods`, `lua.status`; затем выполнить Python-диагностику. До успешной загрузки lua/aic_body никаких spawn-команд.

## Подключение Python Bridge без создания тела

Из PowerShell в проекте, после ручного запуска тестового мира:

```powershell
& $Python -m companion diagnose --game $Game
& $Python -m companion status --game $Game
Test-Path -LiteralPath "$Game\emf\bridge.txt"
Get-Content -LiteralPath "$Game\emf\emf_core.log" -Tail 100
```

Проверить одновременно:

- hello: `protocol=1`, `emf=0.3.2`, `api=20`, `game_build=1273043`, `process=client`;
- game.world: `status=running`, `kind=server`, LOCAL `slot` от 1 до 10;
- game.character: `storage=local`, `slot` от 1 до 16, выбранное имя `Body Test`;
- player.id существует; body.state: `mode=absent`, `recovery_required=false`, нет body_error.

`diagnose` с внешним `ok=true` означает получение диагностики, **не разрешение спавна**: внутри может быть `body_error`. Нужна вся совокупность условий. `bridge.txt` создаёт сам работающий EMF; не создавать его вручную. Канал — `\\.\pipe\emf-bridge-<pid>`, не TCP-порт. Можно явно указать `--pid` вместо `--game`. Python и Steam должны работать от того же Windows-пользователя с одинаковым уровнем прав.

## spawn → follow → stay → dismiss

Перед этим должны быть отдельно разрешены игровые изменения и выполнены предыдущие шаги. Профиль создать один раз (команда не перезаписывает существующий):

```powershell
& $Python -m companion profile-init --name 'Спутник'
```

В следующем блоке **1 и 2 — только пример**, заменить фактическими LOCAL слотами из diagnose; имя также должно точно совпасть. Профиль хранит UUID личности, а не `entityId`.

```powershell
$BodyArgs = @('--game', $Game, '--profile', 'runtime/personality.json',
              '--world-slot', '1', '--character-slot', '2',
              '--character-name', 'Body Test', '--allow-game-mutations')
& $Python -m companion spawn @BodyArgs --request-id trial1-spawn
```

Дождаться exit code=0 и `request.status=succeeded`, увидеть одного Vukah рядом. `faction=11`, `ready=true`, положительное здоровье, цель guard — владелец. Spawn уже включает следование. Если модель не появилась, атакует игрока или ответ не подтверждён — не продолжать нормальный сценарий; сохранить диагностику и перейти к разбору/разрешённой очистке.

```powershell
& $Python -m companion follow @BodyArgs --request-id trial1-follow
```

После succeeded пройти 10–20 метров по ровной открытой поверхности и визуально проверить движение за игроком. Получить status. Подтверждение команды проверяет guard/proximity в нескольких тиках; оно **не доказывает** длительную навигацию, лестницы или обход препятствий.

```powershell
& $Python -m companion stay @BodyArgs --request-id trial1-stay
```

После succeeded появляется служебная бочка-маркер у тела; guard_target должен равняться marker_id. Отойти на 10–20 метров, проверить удержание места. Это штатный guard вокруг маркера, не заморозка: возможны движение и бой.

```powershell
& $Python -m companion dismiss @BodyArgs --request-id trial1-dismiss
& $Python -m companion status --game $Game
```

Успех завершения: dismiss succeeded, затем `mode=absent`, `recovery_required=false`, нет entity_id и marker_id; в мире нет ни тела, ни бочки. JSON может опускать отсутствующие ключи. Только после проверки пользователь выходит из мира.

При ошибке/таймауте не запускать оставшиеся команды одним блоком. Сначала прочитать статус **того же** запроса:

```powershell
& $Python -m companion status --game $Game --request-id trial1-spawn
```

Не отправлять новый spawn при неизвестном исходе. После исправления проблемы удаление тела допустимо отдельным dismiss, только если адаптер сохранил идентичность и не находится в recovery_required. Не подставлять entityId вручную. После перезапуска epoch меняется, старый request ID не является ссылкой на новую сущность.

## Логи и разбор ошибок

Python создаёт отдельный `C:\Enshrouded-ai-companion\runtime\logs\<UTC>-<UUID>.jsonl` на каждый запуск CLI. Путь печатается в stderr. В stdout остаётся JSON-результат. Записываются UTC, elapsed_ms, invocation, connect, hello/state, отправленные console-команды, полные ответы, request ID/epoch, итог/ошибка. Логи содержат локальные пути, имя персонажа и координаты — учитывать при публикации отчёта. Профиль личности целиком в журнал не пишется. Ошибка открытия журнала останавливает команду до соединения; ошибка записи после отправки явно сообщается и не вызывает повтор команды/прерывание проверки.

В `D:\SteamLibrary\steamapps\common\Enshrouded\emf\emf_core.log` искать `AIC_REQUEST`, `AIC_STATE`, `Body adapter`, сообщения Lua и bridge. Состояния пишутся при изменении, без спама на каждом тике. Перед следующим запуском сохранить лог в проекте: EMF может начать новый журнал.

```powershell
Get-ChildItem .\runtime\logs -Filter '*.jsonl' | Sort-Object LastWriteTime -Descending | Select-Object -First 5
Select-String -LiteralPath "$Game\emf\emf_core.log" -Pattern 'AIC_|Body adapter|bridge|lua|error'
```

| Ошибка / наблюдение | Что проверить и когда остановиться |
|---|---|
| Нет `emf_core.log` | Наличие и происхождение loader/core DLL, сообщения защиты Windows; не скачивать отдельные DLL с посторонних сайтов |
| Нет `bridge.txt`, connect error | Игра запущена пользователем, bridge=1, правильный путь/PID, одинаковые права; наличие файла само по себе не гарантирует живой pipe |
| `adapter_reply_missing_or_ambiguous`, `console_refused`, body_error | Lua-host 1.9.0, enabled, правильная папка мода, локальный мир уже загружен, `lua.status`, лог |
| `unsupported_emf`, `unsupported_game_build_or_process` | Остановиться, перепроверить версии; не обходить проверки |
| `wrong_test_world`, `wrong_test_character`, `host_player_missing` | Уточнить LOCAL слоты, точное имя, завершение загрузки мира |
| `verification_timeout_outcome_unknown`, `bridge_error_outcome_unknown` | Действие могло выполниться; status по прежнему request ID, никаких автоматических повторов spawn |
| `body_command_failed` | Смотреть вложенные request.code и state.last_error; failed не гарантирует отсутствие тела |
| `recovery_required`, `identity_changed`, `stale_epoch` | Сохранить логи, остановить сценарий; не стирать runtime.lock и не обходить проверки идентичности |
| Не удалилось тело/бочка | Не считать тест завершённым; сохранить логи, закрыть только тестовый мир при невозможности очистки, согласовать его восстановление |

Если нужен откат: закрыть игру и Steam после синхронизации, сначала отдельно сохранить неудачное тестовое состояние. Использовать проверенную вторую копию LOCAL набора персонаж+global+мир, только после согласования конкретных файлов. Скрипт не выполняет restore. Удаление модов не удаляет сохранённый маркер. Для удаления EMF применять штатный uninstall с проверенным планом; Steam-проверка файлов сама по себе не убирает добавленные DLL. Не редактировать Lua и не выключать адаптер с живым телом.
