## Реализация

`scripts/local_interactive_spawn.py` и `companion/interactive_spawn.py` выполняют проверку пакета/receipt/backup/истории, подключение к указанному PID, prepare, wait, локальное подтверждение и единственный spawn в одном Python-процессе. Между READY, нажатием Y и отправкой команды нет чата Codex, subprocess или повторного подключения Bridge.

Сохранены Lua-контроллер0.1.0, Observer, EMF и все установленные файлы. Остаются штатные проверки build/version/mods, LOCAL Body Test / AI Body Test slot1/1, живого игрока, session, позиции, Ground/Path, времени, durable intent и UNUSED→SPENT latch. Контракт20s отсчитывается от начала probe, не от READY. Изначальное окно подтверждения минимум8s+2s reserve; после отпускания клавиш и вывода приглашения остаток также должен быть ≥10s. Последние2s резервируются для отправки, а не продлевают deadline.

Ввод через `msvcrt.getwch()` без Enter разрешён только для настоящего Windows console stdin/stdout. Pipe, redirect и неподдерживаемая консоль отвергаются до подключения. `GetConsoleMode` проверяет console input, `GetAsyncKeyState` используется для проверки отпускания Y/N/ESC.

- Старый ввод очищается до probe и после READY. Ввод Y во время ожидания отбрасывается.
- После READY CLI выводит координаты, ждёт отпускания клавиш и200ms без раннего ввода, затем показывает приглашение. Ввод, пришедший во время вывода приглашения, не считается согласием. Удерживаемая заранее Y не подтверждает spawn.
- Свежая Y/y после приглашения означает ровно один spawn, подтверждение осмотра места и принятие ранее оговорённого риска disposable-мира. N/n или ESC отменяют. Enter и другие клавиши не подтверждают.
- N/ESC во время ожидания Ground/Path учитываются между RPC; уже отправленный read-only query не отменяется внутри EMF. Его поздний callback сам по себе не создаёт NPC.
- Показывается обратный отсчёт до отмены. Deadline, недостаточное окно, скачок часов, Ctrl+C или ошибка прекращают процедуру без повторов.
- Результат и локальное согласие записываются эксклюзивно. `interactive-started.json` сохраняется при отмене/ошибке и блокирует повторный запуск этого эксперимента. Общий родительский spawn-intent блокирует все попытки; просрочка после его записи не допускает retry.
- Generic spawn CLI с обычными флагами не может подтвердить этот план: требуется локальный key gate. Подтверждение привязано к nonce текущего probe и потребляется один раз.

## Одна команда PowerShell для будущего ручного эксперимента

Перед отдельным игровым тестом повторить closed preflight с новым планом; если игра или сохранения изменились с подготовки, остановиться и подготовить актуальный baseline/backup. Запускает и загружает игру только пользователь. Выбрать LOCAL Body Test / AI Body Test slot1, открытое сухое ровное место без врагов/огня/обрыва, осмотреть область примерно4m по мировой+X. Персонаж должен оставаться неподвижным. Нужны английские клавиши Y/N.

Открыть обычный PowerShell/Windows Terminal под тем же пользователем, что и игра, без повышения прав. Не использовать pipe, перенаправление ввода/вывода или PowerShell ISE. После загрузки мира выполнить **одну строку**:

```powershell
& 'C:\Enshrouded-ai-companion\.tools\python\python.exe' 'C:\Enshrouded-ai-companion\scripts\local_interactive_spawn.py' --plan 'C:\Enshrouded-ai-companion\runtime\stage10_11_2\continuation-plan.json' --sha256 2d3cd9c0bbef8cd8135c2775fe1322296b8511bc5368e4a7fdc0e3e9a2448989 --pid (Get-Process -Name enshrouded -ErrorAction Stop).Id
```

Команда не запускает игру. Отсутствие/неоднозначность процесса приведёт к ошибке аргументов. Она запускает probe: повторять команду после отмены или ошибки нельзя. Не нажимать Y заранее. После READY прочитать координаты, дождаться приглашения, затем Y для одного spawn либо N/ESC для отмены. Чат Codex не используется для передачи согласия.

Положительный ответ API/ID ещё не доказывает правильный внешний вид или мирный AI. После успешного ответа нужна визуальная проверка пользователя и отдельное read-only наблюдение30–60s; этот CLI не автоматизирует наблюдение и не вызывает destroy. При ошибке/неизвестном результате не повторять вызов, сохранить терминал, вручную закрыть игру и выполнить post-close audit по новой сессии. После настоящего spawn изменение latch должно отдельно атрибутироваться по intent; старый no-spawn аудит нельзя использовать как готовое подтверждение успеха. Restore/rollback не выполняются автоматически.

## Проверки и ограничения

Целевые тесты используют fake clock, keyboard и transport: свежаяY без Enter, lowercase, N/ESC, отмена при arming/wait, deadline, ранний/буферизованный/удерживаемый ввод, новый press после release, extended-key scan-code, clock jump, задержка записи согласия, generic CLI bypass, предыдущая session, смена контекста, повтор после отмены/успеха и потерянного ответа, non-console rejection.

Реальные нажатия в Windows-терминале и live spawn этим этапом не испытаны. GetAsyncKeyState/console behavior в конкретном терминале проверяется при отдельном запуске; при ошибке fail closed, без изменения прав. Безопасность/идентичность и поведение созданного NPC по-прежнему ограничены существующим экспериментальным контрактом. `spawn_ready=false`, `production_spawn_ready=false`, `render=UNKNOWN`.
